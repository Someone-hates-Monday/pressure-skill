# 证据型推断与回复 — Agent 备忘（无文献引用版）

用于 **`readiness.portrait_depth` = `deep`** 或用户材料较足时：提高推断与话术的可核对性，减少套话。

## 1. 利益 vs 立场

- **立场**：对方嘴上要的（「今天必须交」「你态度有问题」）。  
- **利益**：背后真正要保全的（可控感、可审计、对上级可交代、不被连坐）。  
- **做法**：话术里用「对齐利益」替代硬顶立场（例：先给可验收的一页 + 时间点，换完整版缓冲）。

## 2. 意图假设要可证伪

每条意图推测尽量带一句 **「若下列事实不成立，则该条作废」**（例：若对方从不读长邮件，则「他要书面留痕」不成立）。  
**minimal** 档：假设少、置信度低、多澄清问句。

## 3. 升级链与渠道

- 对方过去 **冷处理 / 抄送上级 / 当面加压 / 只回「嗯」** 等模式，若画像或对话里有依据，可写进意图；无依据则不要编。  
- **书面 vs 口头**：涉及绩效、扯皮、责任切割时，倾向建议用户 **邮件留痕** 或 **纪要确认**，但不要替用户做违法或伪造证据的指导。

## 4. 具体请求结构（话术里用）

- **可执行块**：时间 + 范围 + 优先级 + 降级版（若只能二选一先交哪块）。  
- **催办块**：阻塞点 + 你需要对方哪一个输出 + 建议时间点 + 你愿意代推的依赖（若画像里有筹码）。

## 5. 与「写明白」类歧义

若同时存在科研交付歧义，**先**对齐 `domain-artefact-cheatsheet.md` 里的载体（公式 / 代码 / 实验叙事），再写意图与澄清邮件草稿。
